## 二、技术栈与版本选型（已拍板）

| 类别 | 选型 | 备注 |
|---|---|---|
| 语言 / JDK | Java 17（Temurin） | 不用 8/11（Boot 3 不支持），不用 18/19/20（非 LTS） |
| 框架 | Spring Boot **3.5.4** | 不用 4.x（库适配风险） |
| 构建 | Maven + Jar + YAML | — |
| 数据库 | MySQL 8.0（阿里云 RDS） | 开发/生产统一引擎 |
| ORM | **MyBatis** `mybatis-spring-boot-starter:3.0.4` | 贴合 mybatis-demo 经验；未用 MyBatis-Plus |
| 连接池 | **HikariCP**（Spring Boot 默认） | 未上 Druid |
| 鉴权 | **auth0 `java-jwt:4.4.0`** | ⚠️ 注意：是 auth0 库，不是 jjwt |
| 参数校验 | `spring-boot-starter-validation` | — |
| 日志 | MyBatis `stdout.StdOutImpl` | 开发期打印 SQL，上线前删 |

> ⚠️ **JWT 库提醒**：pom 用的是 `com.auth0:java-jwt`，写 `JwtUtil` 必须用 `JWT.create() / JWT.require()` 风格，**不能照搬 `io.jsonwebtoken:jjwt` 的 `Jwts.builder()`**（两者 API 完全不同）。

## 五、⚠️ 已知待修复问题（影响全队，需尽快处理）

| # | 问题 | 现状 | 修复方案 |
|---|---|---|---|
| 1 | **包扫描不到组件** | 启动类在 `com.sixth.soul_trail`，而 `pojo`/`service` 在 `com.sixth`（兄弟包），默认扫不到 | 启动类加 `@ComponentScan("com.sixth")` + `@MapperScan("com.sixth.mapper")`；或把包整体挪到 `com.sixth.soul_trail` 下 |
| 2 | **Mapper 层缺失** | 无 `UserMapper` 接口、无 `resources/mapper/*.xml`，但 yaml 已指向 `classpath:mapper/*.xml` | 建 `UserMapper.java` + `UserMapper.xml`（登录查用户要用） |
| 3 | **pom 重复依赖** | `spring-boot-starter-test` 声明了两次 | 删掉一处 |
| 4 | **别名包名写错** | yaml 写 `type-aliases-package: com.sixth.soul_trail.pojo`，实际包是 `com.sixth.pojo` | 改回 `com.sixth.pojo`（配合第 1 点） |
| 5 | **空实现无注解** | `UserServiceImpl` 无 `@Service` | A 补 `@Service` + 注册逻辑 + 注入 `UserMapper` |
| 6 | **建表未确认** | `soultraildb` 内 `user`/`diary`/`diary_keyword` 三张表 SQL 是否已执行未知 | 连上库后执行建表 SQL，否则报 `Table doesn't exist` |

### 后端三人统一约定（B 定义）
- 所有接口返回统一 `{ code, message, data }`（用 `Result<T>`）
- 异常统一由 `GlobalExceptionHandler` 捕获，不向前端抛堆栈
- 当前登录用户 ID：经 JWT 解析后由 `SecurityUtil.getCurrentUserId()` 获取
- 跨域：开发期由前端 Vite proxy 或后端 `CorsConfig` 处理
